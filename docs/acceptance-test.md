# 受け入れテスト（v0.1）

MVP（[mvp.md](mvp.md)）の機能が、この Mac でひととおり正しく動くことを確かめる。

- 実施日：2026-10-07〜
- 環境：MacBook Air（M1）、macOS 26.3、EDIFIER W820NB Plus
- アプリ：スキーム `BatonMac`（本物の Bluetooth）で起動したもの

結果の記号：✅ 期待どおり ／ ❌ 期待と違う ／ － 実施しない

## A. 起動と常駐

| ID | 手順 | 期待する結果 | 結果 |
|---|---|---|---|
| A1 | Baton を起動する | メニューバーにヘッドホンのアイコンが出る。Dock にはアイコンが出ない | ✅ |
| A2 | メニューの「Baton を終了」を押す | アプリが終了し、メニューバーのアイコンが消える | ✅ |
| A3 | メニューの「ログイン時に起動」をオンにする | システム設定 > 一般 > ログイン項目 に Baton が表示される | ✅ |
| A4 | 「ログイン時に起動」をオフにする | ログイン項目から Baton が消える | ✅ |

## B. 機器の登録と解除

| ID | 手順 | 期待する結果 | 結果 |
|---|---|---|---|
| B1 | メニューの「機器を登録・解除…」を押す | 登録画面のウィンドウが、前面に開く | ✅ |

| B6 | B5 の後、もう一度 EDIFIER を登録する | 以降のテストのために、登録された状態に戻す | ✅ |

## C. この Mac での接続と切断

準備：音声の出力先を「Mac のスピーカー」にし、音楽を流しておく。

| ID | 手順 | 期待する結果 | 結果 |
|---|---|---|---|
| C1 | EDIFIER が接続中の状態で、メニューの「切断」を押す | 「切断しています…」とくるくるが出た後、「未接続」になる。音がスピーカーから鳴る | ✅ |
| C2 | メニューの「接続」を押す | 「接続しています…」とくるくるが出た後、「この Mac に接続中」になる。音がヘッドホンから鳴る | ✅ |
| C3 | 接続・切断の途中に、ボタンを見る | ボタンが押せない（灰色） | ✅ |
| C4 | ヘッドホンの電源を切る | メニューの表示が「未接続」になる | ✅ |
| C5 | ヘッドホンの電源を入れる | メニューの表示が「この Mac に接続中」になる | ✅ |
| C6 | ヘッドホンの電源を切った状態で、メニューの「接続」を押す | しばらくして、赤いメッセージ「〜に接続できませんでした。機器の電源と距離、…を確認してください」が出る | ✅ |
| C7 | C6 の後、ヘッドホンの電源を入れて、「接続」を押す | 接続でき、赤いメッセージが消える | ✅ |

## D. 離れるとき・戻ってきたとき

準備：EDIFIER を接続中にしておく。

| ID | 手順 | 期待する結果 | 結果 |
|---|---|---|---|
| D1 | Apple メニュー > スリープ で Mac をスリープさせ、30秒ほど待ってから起こし、ロックを解除する | スリープで EDIFIER が切れ、ロックを解除した後に再接続される | ✅ |
| D2 | 電源ボタンを押して画面をロックし、30秒ほど待ってから、ロックを解除する | ロックで EDIFIER が切れ、ロックを解除した後に再接続される | ✅ |
| D3 | 電源ボタンでロックした後、キーを押して画面を点ける（ロック画面のまま、解除しない） | ロック画面のままでは再接続されない（メニューは解除後に確認する） | ✅ |
| D4 | ふたを閉じて30秒ほど待ってから開き、ロックを解除する（外部モニターにつないでいない状態で） | ふたを閉じると EDIFIER が切れ、ロックを解除した後に再接続される | ✅ |
| D5 | EDIFIER を「切断」してから、電源ボタンでロックし、ロックを解除する | 離れる前に接続していなかったので、再接続されない | ✅ |
| D6 | EDIFIER を接続したまま一晩スリープさせ、朝に起こしてロックを解除する | ロックを解除した後に再接続される | |

## メモ

- D1・D4 を行った時間帯（2026-10-07 20時以降）の電源ログに、Sleep の記録がなかった。スリープの通知の後に、スリープが取りやめになっていた可能性がある（その場合も、「離れた」で切断・「戻ってきた」で再接続されるので、見た目は期待どおりになる）
- 「本当にスリープして、起きた後に再接続される」流れは、D6（一晩）で確かめ、電源ログで実際にスリープしていたことも確認する
- 本当にスリープした状態での切断は、受け入れテストの前（2026-10-07 14:58、電源ログに Software Sleep の記録あり）に確認済み
