# 技術検証：IOBluetooth

検証日：2026-10-01
Issue：#11

## 1. 目的

仕様の前提（Mac の Bluetooth を IOBluetooth で操作できること）が実機で成り立つかを確かめる。うまくいかない項目があれば、仕様を見直す。

## 2. 結論

**IOBluetooth で、MVP に必要な機能は実現できる。仕様の大きな見直しは不要。**

| 項目 | 結果 | 要点 |
|---|---|---|
| 機器の一覧 | ✅ | 名前・アドレス・接続状態を取れる。音声機器以外（キーボード、マウス）も含まれる |
| 接続・切断 | ✅ | どちらもできる。接続後に音声の出力先が自動で切り替わるかは、そのときの出力先による |
| Sandbox | ✅ | Bluetooth の権限を付ければ動く。権限がないと、エラーにならずに一覧が空になる |
| スリープ | ⚠️ | スリープ中もヘッドホンはつながったままだった。スリープ時の切断（仕様書 7）が必要 |
| 接続の通知 | ✅ | 接続・切断の通知が届く。同じ通知が重なって届くことがある |

## 3. 検証の環境

| 項目 | 内容 |
|---|---|
| Mac | MacBook Air（M1）、macOS 26.3 |
| Xcode | 26.3 |
| 検証に使った機器 | EDIFIER W820NB Plus（HFP、AVRCP、A2DP に対応） |
| 同時に接続していた機器 | HHKB-Hybrid_2（キーボード、BLE）、EM01 NL（マウス、BLE）、DELL S2725HS（モニター。音声の出力先になる） |
| 検証用のコード | ブランチ `spike/iobluetooth`（main にはマージしない） |

検証用のアプリは、BatonMac に一時的な画面を追加したもの。機器の一覧、接続・切断のボタン、接続・切断とスリープ・復帰のログ、音声の出力先（CoreAudio）の表示を持つ。

## 4. 結果の詳細

### 4.1 機器の一覧

- `IOBluetoothDevice.pairedDevices()` で、ペアリング済みの機器を取得できた
- 名前（`name`）、アドレス（`addressString`）、接続状態（`isConnected()`）、ペアリング済みか（`isPaired()`）を取れる
- **音声機器以外も含まれる**。BLE でつながっているキーボード（HHKB）とマウス（EM01）も一覧に出た
- 音声機器かどうかは、機器の種類（`deviceClassMajor` が Audio）で判定できた
- **アドレスの表記が、場所によって違う**
  - IOBluetooth の `addressString`：`08-f0-b6-f4-7f-fb`（小文字、ハイフン区切り）
  - macOS のシステム情報：`08:F0:B6:F4:7F:FB`（大文字、コロン区切り）

### 4.2 接続・切断

**切断（`closeConnection()`）**

- すぐに「成功」が返る
- 直後の `isConnected()` は、まだ `true` を返す。約1秒後に切断の通知が届き、そこで実際に切断される
- 音声の出力先は、約3秒後に他の機器に切り替わった。ヘッドホンの音も止まった

**接続（`openConnection()`）**

- 「成功」が返り、`isConnected()` も `true` になった
- **接続が終わるまで処理が戻らない**。かかった時間は 1.9〜8.8秒と、ばらつきが大きかった
- その間は画面が固まる。固まっている間にボタンを押すと、固まりが解けた後にその操作が実行された
- **接続後に音声の出力先が自動で切り替わるかは、接続する前の出力先による**

| 接続する前の出力先 | 接続後の出力先 |
|---|---|
| Mac のスピーカー | ✅ EDIFIER に切り替わった（2回とも） |
| DELL のモニター | ❌ 切り替わらなかった（2回とも） |

- 比較として、ヘッドホンの電源を入れて**ヘッドホンの側から接続した場合**は、出力先がモニターでもヘッドホンに切り替わった
- モニターの件は、モニター側の事情の可能性が高いため、MVP では追いかけない。必要になったら、接続後に CoreAudio で出力先を切り替える処理で対応できる見込み（検証用のアプリで処理は試作済み。実機での確認はしていない）

### 4.3 Sandbox

| 条件 | 結果 |
|---|---|
| Sandbox ON、Bluetooth の権限なし | 機器の一覧が**空**になる。`pairedDevices()` は `nil` ではなく空の一覧を返す。エラーも、許可のダイアログも出ない |
| Sandbox ON、Bluetooth の権限あり（`ENABLE_RESOURCE_ACCESS_BLUETOOTH = YES`） | 一覧・接続・切断・通知のすべてが動いた |

- 権限がないことを、アプリ側で検知する方法が見つからなかった（エラーにならない。システムのログにも拒否の記録が見つからなかった）
- CoreAudio（音声の出力先の取得）は、Bluetooth の権限がなくても動いた

### 4.4 スリープ

`NSWorkspace` のスリープ・復帰の通知でログを取り、電源ログ（`pmset -g log`）で実際にスリープしたかを確かめた。

| 試行 | 電源ログ | Baton のログ |
|---|---|---|
| 1回目 | 画面が消えてすぐについただけ（スリープしていない） | 「スリープに入る」と「復帰した」の通知が2秒差で届いた |
| 2回目 | 通知の約5秒後にスリープ → 19秒後に復帰（Bluetooth のキーボードかマウスの信号で起きた） | スリープの前後とも、EDIFIER は接続中 |

- **スリープ中も、EDIFIER はつながったままだったと考えられる**
  - スリープの前後とも接続中で、スリープの間に EDIFIER の切断・接続の通知は届かなかった
  - 一方、キーボードとマウスは、復帰したときに接続の通知が届いた（スリープ中に一度切れて、つなぎ直された）
- 「スリープに入る」の通知から実際にスリープするまで、**約5秒**あった
- **実際にはスリープしなかった場合も**、「スリープに入る」と「復帰した」の通知が届いた
- Bluetooth のキーボードやマウスの信号で、すぐに復帰することがある
- スリープしていた時間が19秒と短いため、長時間のスリープでも同じかは確かめていない

### 4.5 接続の通知

- `IOBluetoothDevice.register(forConnectNotifications:selector:)` で、どの機器の接続も通知される
- **登録した時点ですでに接続中の機器についても、通知が届いた**（起動時に EDIFIER、キーボード、マウスの通知が届いた）
- 切断の通知は、機器ごとに `register(forDisconnectNotification:selector:)` で登録すると届いた
- ヘッドホンの電源を切る・入れる操作でも、切断・接続の通知が届いた
- **同じ通知が重なって届くことがある**
  - 起動時、キーボードとマウスの接続の通知は2回ずつ届いた
  - `openConnection()` の後、EDIFIER の接続の通知が最大4回届いた

## 5. 本番の実装への反映

| フェーズ | 反映すること | 根拠 |
|---|---|---|
| 3 | 機器を登録する画面では、音声機器だけを表示する | 4.1 |
| 3 | アドレスは、比較する前に表記をそろえる（大文字・小文字、区切り文字）。iPhone との照合（仕様書 14.1）でも同じ | 4.1 |
| 3 | 接続状態は、`isConnected()` の直後の値ではなく、接続・切断の通知で判断する | 4.2 |
