# Baton 仕様書（Bluetooth接続切り替えアプリ）

最終更新：2026-10-08

MVPの範囲は [mvp.md](mvp.md) を参照。

## 1. 概要

1台のBluetooth機器（イヤホンなど）を複数の端末で使うとき、これまでは「接続元の端末で切断 → 接続先の端末で接続」という2か所での操作が必要だった。

本アプリは各端末に常駐・インストールし、接続先の端末で操作するだけで、接続元の切断から接続先への接続までを完結させる。

## 2. 基本方針

- 操作は接続先の端末だけで完結する（接続元の端末には触らない）
- 接続できるのは自分の端末だけ。他の端末に対しては切断の依頼だけができる
- 同じLAN内の端末同士で通信する（サーバー不要）
- 個人利用（App Storeでは配布しない）
- **登録機器がどの端末に接続中かを確認できること**を最優先とする

## 3. 対応範囲

| 接続元 → 接続先 | 対応 | 理由 |
|---|---|---|
| Mac → Mac | ✅ 対応 | 接続元のMacがアプリで切断でき、接続先のMacがアプリで接続できる |
| Mac → iPhone | ✅ 対応 | 接続元のMacがアプリで切断できる。iPhoneでの接続はルート選択ボタンのタップで行う（接続先での操作なので方針内） |
| iPhone → Mac | ❌ 非対応 | iPhoneのアプリは、外部からの依頼で自分のBluetoothを切断できない（公開APIがない） |
| iPhone → iPhone | ❌ 非対応 | 同上 |

## 4. 動作環境

| 項目 | 内容 |
|---|---|
| Mac | macOS 14 以上（MenuBarExtra・SMAppService は13以上、`@Observable`・SettingsLink が14以上のため） |
| iPhone | iOS 17 以上（`@Observable` が17以上のため） |
| ネットワーク | 全端末が同じLAN（Wi-Fi）に接続していること |
| 管理対象の機器 | 複数台を登録できる |

## 5. 機能一覧

### 5.1 Macアプリ（メニューバー常駐）

| 機能 | 内容 |
|---|---|
| Bluetooth機器の登録と解除 | ペアリング済みのBluetooth機器から、管理対象を選んで登録・解除する |
| 接続機器の切り替え | 登録機器をこのMacに切り替える（接続元に切断を依頼 → 完了後にこのMacで接続） |
| 登録機器の接続状態の表示 | 登録機器ごとに、どのMacに接続中か（またはどのMacにも接続していないか）を表示する。応答のないMacは「応答なし」と、最後に確認できた時刻・状態を表示する（→ 6.5） |
| 選択した機器の接続と切断 | 登録機器を、このMacで接続・切断する |
| 切断依頼の受け付け | ペアリング済みの端末からの切断依頼を受け、対象機器を切断して結果を返す（自動） |
| 切断時の通知 | 切断依頼によって機器を切断したとき、「〇〇が△△に切り替わりました」と通知する（〇〇は機器名、△△は依頼元の表示名）。設定でオン・オフできる。デフォルトON |
| スリープ時の切断と復帰時の再接続 | 切断のきっかけ（画面のロック、スリープ、画面の消灯）ごとにオン・オフできる。Mac 全体で1つの設定。詳細は「7. スリープ時の動作」 |
| 端末のペアリング | 他の端末とPINコードでペアリングする（コードの表示・入力の両方） |
| ペアリング済み端末の一覧と解除 | ペアリング済みの端末を表示し、解除できる |
| 設定 | ・このMacの表示名（→ 5.3）<br>・ログイン時の自動起動<br>・離れるときの切断のきっかけ（→ 7）<br>・応答の待ち時間（→ 8）<br>・切断時の通知のオン・オフ |

### 5.2 iPhoneアプリ

| 機能 | 内容 |
|---|---|
| Macから切断 | 登録機器を接続中のMacに切断を依頼する。切断後、そのままiPhoneで使えるようにルート選択ボタンを表示する（使わない場合は閉じるだけ） |
| 登録機器の接続状態の表示 | 登録機器ごとの接続状態を表示する。登録機器の一覧はMacから受け取る（→ 5.4） |
| Macとのペアリング | Macに表示されたPINコードを入力してペアリングする |
| ペアリング済みMacの一覧と解除 | ペアリング済みのMacを表示し、解除できる |
| 設定 | ・このiPhoneの表示名（→ 5.3）<br>・応答の待ち時間（→ 8） |

#### iPhoneでの「切り替え」の位置づけ

- iPhoneのアプリは自分のBluetoothを接続できないため、切り替え処理に接続を含められない。アプリの処理としては、実質「他端末（Mac）のBluetooth接続の切断」だけになる
- そのため「切り替え」と「Macでの切断」を分けず、「Macから切断」の1機能にまとめる
- 接続は、切断後に表示するルート選択ボタンをユーザーがタップして行う
- 機器によっては、Macから切断されるとiPhoneに自動で再接続するものもあり、その場合はタップも不要になる

#### iPhoneの制約

- ペアリング済みのBluetooth機器の一覧を取得できないため、機器の登録はMacで行う
- 自分のBluetoothを接続・切断するAPIがないため、接続は標準のルート選択ボタン（AVRoutePickerView）をユーザーがタップして行う
- 自分の接続状態は「現在の音声の出力先」からしか判定できない。接続していても出力先になっていない機器は判定できない
- バックグラウンドで通信を待ち受けられないため、iPhoneは常に「依頼する側」になる。**他の端末からiPhoneの接続状態を問い合わせることはできない**

### 5.3 端末の表示名

- 各端末は表示名を持ち、接続状態の表示・エラーメッセージ・ペアリング済み端末の一覧で使う
- Macの初期値はコンピュータ名（システム設定 > 一般 > 共有 で設定する名前。例：「RyumaのMacBook Air」）
- iPhoneの初期値は「iPhone」（iOS 16以降、アプリから端末名を取得できないため）
- アプリの設定で任意の名前（「Mac1」「仕事用」など）に変更できる
- 重複の防止
  - Bonjourのサービス名は同じLAN内で重複すると自動で「(2)」などが付く
  - 登録・ペアリング時に同じ表示名の端末があれば警告する

### 5.4 登録機器の識別と一覧の統合

- 登録機器はBluetoothアドレスで識別する（端末をまたいで同じ機器かどうかの判定に使う）
- 登録はMacごとに行うため、Macによって登録機器が異なることがある
- iPhoneは、ペアリング済みの全Macから登録機器の一覧を受け取り、Bluetoothアドレスでまとめて表示する

## 6. 切り替えの流れ

### 6.1 Mac A → Mac B（Mac Bで操作）

1. Mac Bで、登録機器の「このMacに接続」を選ぶ
2. Mac Bが、ペアリング済みのMacに接続状態を問い合わせる
3. 機器を接続中のMac（Mac A）に、切断を依頼する
4. Mac Aが機器を切断し、結果を返す
5. Mac Bが機器に接続する
6. 結果を表示する

どのMacにも接続されていない場合は、3〜4を省略して5に進む（応答のないMacがある場合は 6.3）。

### 6.2 Mac → iPhone（iPhoneで操作）

1. iPhoneで、登録機器の「Macから切断」を選ぶ
2. iPhoneが、ペアリング済みのMacに接続状態を問い合わせる
3. 機器を接続中のMacに、切断を依頼する
4. Macが機器を切断し、結果を返す
5. iPhoneがルート選択ボタンを表示し、ユーザーがタップして機器を選ぶ（iPhoneで使わない場合は閉じる。機器がiPhoneに自動で再接続した場合は不要）

アプリが自動で行うのは1〜4（Macの切断）までで、5の接続はユーザーの操作になる。

### 6.3 応答のないMacがある場合

接続状態を問い合わせたとき、一定時間内に応答しないMacがある場合の扱い。

- 接続状態の表示では、そのMacを「〇〇：応答なし」と表示する
- 応答したMacの中に機器を接続中のMacがあれば、通常どおりそのMacに切断を依頼する
- 応答したMacのどれにも接続されていない場合は、**そのまま接続を試す**
  - Mac：このMacで接続を試す。失敗した場合は「〇〇が応答しません。〇〇で直接切断してください」と表示する（〇〇は応答のなかったMacの表示名）
  - iPhone：ルート選択ボタンを表示する。あわせて応答のなかったMacの表示名を表示する

### 6.4 機器がiPhoneに接続中の場合

- 他の端末からiPhoneの接続状態は分からないため、Macからは「どのMacにも未接続」に見える
- Macでの接続が失敗した場合は、接続失敗のエラー（→ 10）で「ほかの端末（iPhoneなど）で使用中でないか」を確認するよう促す

### 6.5 最後に確認できた状態の表示

常にすべての端末が動いているとは限らず、すべての端末が「応答なし」になることもある。その場合でも機器の居場所の見当がつくように、最後に確認できた状態を使って表示する。

```
Sony WH-1000XM5 ─ Mac A に接続中だった（最終確認 2時間前）   ← まとめの行
  Mac A：応答なし（最終確認 2時間前・接続中）
  Mac C：スリープ中（10:32から・接続なし）
  このMac：未接続
```

#### 機器ごとのまとめの行

上から順に判定し、最初に当てはまったものを表示する。

| # | 条件 | 表示 | 情報の種類 |
|---|---|---|---|
| 1 | このMacに接続中 | このMacに接続中 | その場で確認した事実 |
| 2 | 応答したMacのどれかに接続中 | Mac A に接続中 | その場で確認した事実 |
| 3 | 応答のないMacのうち、記録が「接続中」のものがある | Mac A に接続中だった（最終確認 2時間前） | 記録からの推測 |
| 4 | 上のどれにも当てはまらない | どのMacにも未接続（応答のないMacがあれば、その最終確認の時刻を添える） | 1・2は事実、応答のないMacの分は推測 |

- 3で「接続中」の記録が複数ある場合は、最終確認がいちばん新しいものを採用する（機器は通常、同時に1台にしかつながらないため）
- 推測の表示は、文字を薄くし、時刻を添えて事実と区別する
- 時刻は「10分前」のような相対表示にする
- **表示だけに使い、切り替えの判断には使わない**。切り替えは 6.3 のとおり、応答がなければそのまま接続を試す

#### 端末ごとの記録

端末ごとに「最終確認の時刻」「接続中の機器（Bluetoothアドレス）」「スリープ中かどうか」を記録し、アプリを再起動しても残す。次のときに更新する。

| きっかけ | 記録の更新内容 |
|---|---|
| status の応答を受け取った | 応答の内容で更新する。スリープ中の印は外す |
| その端末への切断依頼が成功した（result） | 切断した機器を「接続なし」にする |
| その端末から sleep を受け取った | sleep に含まれる接続状態で更新し、スリープ中の印を付ける |

#### スリープ前の知らせ（sleep）

- スリープに入るMacは、機器の切断（→ 7）を終えた後に、他の端末へ sleep メッセージを送る
- sleep には、切断を終えた後の接続状態（まだ接続中の機器のBluetoothアドレス）を含める。通常は空になるが、「スリープに入るとき」の切断をオフにしている場合はつながったまま残るため、その分が含まれる
- 受け取った側は、その端末の記録を更新し、「応答なし」ではなく「スリープ中（10:32から）」と表示する
- スリープ直前は使える時間が短いため、送れたら送る程度とする。届かなかった端末では、その端末は「応答なし」と表示される
- 知らせが届くのは、そのとき起きている端末だけ。寝ていた端末は、次に status で確認するまで古い記録のままになる

## 7. スリープ時の動作（Mac）

### 切断のきっかけの設定

どのきっかけで切断するかを、メニューの「離れるときに切断」で選べる。Mac 全体で1つの設定で、すべての登録機器に使う。

| きっかけ | 初期値 | 理由 |
|---|---|---|
| 画面をロックしたとき | オン | 電源ボタンを押しても Mac はすぐにはスリープせず、ヘッドホンがつながっている間は自動でもスリープしないため（[検証結果](spikes/sleep-reconnect.md)） |
| スリープに入るとき | オン | |
| 画面が消えたとき（ディスプレイのスリープ） | オフ | 画面を消したまま音楽を聴いていることがあるため |

- 再接続は設定にしない。戻ってきたときは、離れるときに切断した機器を必ず再接続する（設定がオフで切断しなかった機器は、記録がないので何もしない）
- 「画面をロックしたとき」をオフにすると、上の理由で、電源ボタンで離れても切断されないことがある。メニューに注意書きを出す
- 機器ごとのオン・オフは、必要になったら追加する

### スリープに入るとき・画面をロックしたとき・画面が消えたとき

- macOSからの通知を受け、そのきっかけの設定がオンなら、接続中の登録機器を切断する
- 切断した機器を「スリープ前にこのMacが接続していた機器」として記録する
- 他の端末に sleep メッセージを送り、切断後の接続状態を知らせる（→ 6.5）

### 離れている間（v0.2）

設定がオンのきっかけで離れてから、戻ってくるまでを「離れている間」とする。そのとき切断する機器がなくても、離れている間になる。

- 離れている間に登録機器がつないできたら（ヘッドホンの電源を入れ直した など）、すぐ切断する。ヘッドホンは最後につないだ端末につなぎに行き、スリープ中の Mac はその接続でダークウェイクして受け付けるため、切らないと寝ている Mac がつかんだままになる（[検証結果](spikes/sleep-reconnect.md) 7）
- スリープ中でも、接続でダークウェイクした数秒の間に切断できる（同 8。切断は0.6〜0.7秒、ダークウェイクは7〜8秒）
- 切断した機器は、戻ってきたら再接続する機器として記録する（戻る前にヘッドホンの電源を先に入れた場合のため）
- 安全弁：同じ機器を5分以内に3回切断したら、戻ってくるまでその機器は切らない。切られても何度もつなぎに来る機器で、Mac が何度も起きて電池が減り続けないようにするため
- 新しい設定は作らない。「離れるときに切断」の設定から自動で決まる（2026-10-08 に決定）

### スリープから復帰したとき・ロックを解除したとき

- 再接続は、ロックを解除したとき（ロックしていなければ、画面が点いたとき）に行う。ダークウェイク（画面を消したまま一時的に起きる状態）やロック画面のままでは行わない（[検証結果](spikes/sleep-reconnect.md) 5）

- 次の両方を満たす機器だけ、自動で再接続する
  - スリープ前にこのMacが接続していた
  - 他の端末がその機器を使っていない
- 復帰直後はネットワークが戻っていないことがあるため、ネットワークの復帰を待ってから問い合わせる
- 他の端末が使用中の場合は再接続せず、記録を消す

#### MVP（v0.1）での扱い

MVP は他の端末と通信しない（[mvp.md](mvp.md)）ため、「他の端末がその機器を使っていない」は問い合わせずに、次のように判断する。

- スリープ前にこの Mac が接続していた機器に、接続を試す
- 他の端末で使用中などで接続に失敗したら、あきらめて記録を消す
- 他の端末への問い合わせは、他の端末とのやり取りを作るときに追加する（時期未定）

### 自動で切断・再接続するとき（まとめ）

| きっかけ | 動き | 設定 |
|---|---|---|
| スリープに入る直前（メニューの「スリープ」、ふたを閉じる など） | 切断する | あり（初期値オン） |
| 画面をロックしたとき（電源ボタン、⌃⌘Q、ロックまでの時間が過ぎた など） | 切断する | あり（初期値オン） |
| 画面が消えたとき（ディスプレイのスリープ） | 切断する | あり（初期値オフ） |
| 離れている間に、登録機器がつないできたとき | 切断する（安全弁あり） | なし（離れるときの設定に従う） |
| ロックを解除したとき | 再接続する | なし |
| 画面が点いた・システムが起きたとき | ロックされていなければ再接続する（ダークウェイクでは再接続しない） | なし |
| Baton の終了、ログアウト、ユーザーの切り替え | 何もしない | |

ロック・スリープ・画面の消灯は、離れ方とロックの設定によって、どれが先に来るか、いくつ来るかが変わる（電源ボタンでは、ロックと画面の消灯が続けて来る）。続けて2回以上来ても、2回目からは切断する機器がないので何もしない。

### 制約

- 電池切れや強制終了では通知が来ないため、切断されない。この場合、他の端末からの切断依頼は「応答なし」のエラーになる
- スリープ中はアプリが動かないため、切断依頼を受け付けられない
- 「スリープに入るとき」の設定がオフなら、スリープ中も接続されたままになる。この間、他の端末からはそのMacが「応答なし」に見える

## 8. 端末間の通信

- 端末の発見：Bonjour（同じLAN内のペアリング済み端末を自動で見つける）。サービスタイプは `_baton._tcp`、サービス名にはMacの表示名を使う
- 通信：TCP上のメッセージ（JSON）
- Macは常に待ち受け、iPhoneはアプリを開いている間だけ通信する
- 応答の待ち時間（タイムアウト）は設定値とする。接続状態の問い合わせ・切断依頼の両方に使う。デフォルト5秒、1〜30秒で変更できる

### メッセージ一覧

| メッセージ | 向き | 内容 |
|---|---|---|
| status | 依頼側 → 各Mac | 問い合わせたい機器のBluetoothアドレスを指定して、接続状態を問い合わせる |
| status（応答） | 各Mac → 依頼側 | 指定された機器のうち、自分が接続中のもの（Bluetoothアドレス）と自分の表示名を返す。自分がその機器を登録しているかどうかは関係ない |
| devices | iPhone → Mac | 登録機器の一覧を要求する |
| devices（応答） | Mac → iPhone | 登録機器の一覧（Bluetoothアドレス・機器名）を返す |
| disconnect | 接続先 → 接続元 | Bluetoothアドレスを指定して、機器の切断を依頼する。依頼された側がその機器を登録しているかどうかは関係ない |
| result | 接続元 → 接続先 | 切断の成功・失敗を返す |
| sleep | スリープに入る端末 → 他の端末 | スリープに入ることと、切断を終えた後の接続状態（接続中の機器のBluetoothアドレス）を知らせる（→ 6.5） |
| pair | 端末間 | ペアリングの開始・PINコードの確認 |

## 9. セキュリティ（端末のペアリング）

- 初回だけ、PINコードで端末同士をペアリングする
  1. 一方の端末から、もう一方にペアリングを申し込む
  2. 申し込まれた側の画面に6桁のコードが表示される
  3. 申し込んだ側でそのコードを入力する
  4. コードをもとに共有キーを作り、両方のキーチェーンに保存する
- 以降の通信は、共有キーによるTLS-PSKで暗号化し、相手を確認する
- ペアリング済みの端末からの依頼だけを受け付ける

### 将来の対応

- 6桁のPINから直接キーを作る方式は、ペアリング時の通信を盗聴されると総当たりで解読される余地がある
- のちに、鍵交換（CryptoKitによるECDH）で共有キーを作り、PINはその確認だけに使う方式へ移行する

## 10. エラー処理

エラー時はメッセージを表示する。

| 状況 | 表示するメッセージ（例） |
|---|---|
| 接続元の端末が応答しない（スリープ中、電池切れ、ネットワーク外など） | 「〇〇が応答しません。〇〇で直接切断してください」 |
| 接続元での切断に失敗した | 「〇〇での切断に失敗しました」 |
| 機器への接続に失敗した（電源オフ、範囲外、iPhoneなどで使用中） | 「〇〇に接続できませんでした。機器の電源と距離、ほかの端末（iPhoneなど）で使用中でないか確認してください」 |
| ネットワークに接続していない | 「ネットワークに接続していません」 |
| ペアリングしていない端末からの依頼 | 受け付けない（表示なし） |

## 13. 開発構成

### 13.1 リポジトリとプロジェクト

MacアプリとiPhoneアプリを1つのリポジトリ・1つのXcodeプロジェクトで管理する。

```
Baton/
├── Baton.xcodeproj           # ターゲット：BatonMac、BatonPhone
├── BatonMac/                 # Macアプリ
├── BatonPhone/               # iPhoneアプリ
├── Packages/BatonKit/        # 共通コード（ローカルのSwift Package）
│   ├── Sources/BatonKit/
│   └── Tests/BatonKitTests/
└── docs/
```

| ターゲット | 対象 | アプリ名 | Bundle ID |
|---|---|---|---|
| BatonMac | macOS | Baton | `Kazue.Baton` |
| BatonPhone | iOS | BatonPhone（`Baton` への変更を検討中） | `Kazue.BatonPhone` |

### 13.2 コードの置き場所

- **BatonKit**：MacとiPhoneで共通のもの（メッセージの定義、Bonjour・TCP・TLS-PSK、ペアリング、キーチェーン、切り替えの判断ロジック）
- **BatonMac**：Macでしか動かないもの（IOBluetooth、MenuBarExtra、NSWorkspace、SMAppService、通知）
- **BatonPhone**：iPhoneでしか動かないもの（AVRoutePickerView、AVAudioSession）
- 判断ロジックはできるだけBatonKitに置き、自動テストできる範囲を広げる

### 13.3 データの保存先

| データ | 保存先 |
|---|---|
| 設定値・登録機器の一覧 | UserDefaults（`@AppStorage`） |
| 他の端末ごとの記録（最終確認の時刻・接続中の機器・スリープ中かどうか） | UserDefaults |
| 共有キー | キーチェーン |

### 13.4 テスト

- テストはBatonKitに Swift Testing で書く
- 実行方法：Xcodeで `BatonMac` スキームを選んで ⌘U、または `swift test --package-path Packages/BatonKit`
- Bluetooth・画面など実機に関わる部分は、アプリを起動して手で確認する

### 13.5 開発環境

| 項目 | 内容 |
|---|---|
| Xcode | 26.3 |
| Swift | 6.2 |
| 署名 | Personal Team（無料のApple ID） |
| 開発の順番 | Macアプリを先に作り、iPhoneアプリは後から作る |

## 14. 未決事項・要検証

### 14.1 実機での検証が必要なもの

| 項目 | 内容 | 状態 |
|---|---|---|
| IOBluetoothで音声までつながるか | `openConnection()` で、機器の音声（A2DPなど）まで接続されるか | ✅ 検証済み。つながる。ただし接続前の出力先によっては、出力先が自動で切り替わらない（[検証結果](spikes/iobluetooth.md) 4.2） |
| IOBluetoothをSandboxの中で使えるか | Bluetoothのentitlementを付ければ、機器の一覧取得・接続・切断ができるか | ✅ 検証済み。使える。権限がないと一覧が空になる（[検証結果](spikes/iobluetooth.md) 4.3） |
| スリープ中のBluetoothの接続 | スリープ中も、ヘッドホンがつながったままか | ✅ つながったまま。Baton が切断しても、ヘッドホンの電源を入れ直すと、スリープ中の Mac がダークウェイクして接続を受け付け、つないだまま寝る（[検証結果](spikes/sleep-reconnect.md) 7）。対策は plan.md フェーズ6 |
| TLS-PSKが使えるか | Network framework の `sec_protocol_options_add_pre_shared_key` で、macOS 14・iOS 17 以上でTLS-PSK通信ができるか | 未検証（通信を作るとき） |
| ローカルネットワークの許可 | Bonjour・TCP通信の初回に出る許可ダイアログと、拒否されたときの動き | 未検証（通信を作るとき） |
| iPhoneの出力先の照合 | `AVAudioSessionPortDescription.uid` に含まれるBluetoothアドレスで照合できるか（シミュレータ不可）。アドレスの表記の違いに注意（[検証結果](spikes/iobluetooth.md) 4.1） | 未検証（iPhoneアプリを作るとき） |

### 14.2 決める必要があるもの

| 項目 | 内容 | 案 |
|---|---|---|
| 登録機器の同期 | ある Mac で登録・解除すると、他の Mac にも反映する。解除の伝え方と、オフラインだった Mac の扱いが課題 | 未定（他の端末とのやり取りを作るときに検討） |
| 接続状態のリアルタイム同期 | IOBluetooth の接続・切断の通知を受けて、他の端末にすぐ知らせる。スリープ中・オフラインの端末には届かないため、status での問い合わせも残す | 未定（他の端末とのやり取りを作るときに検討） |
| メッセージの詳細 | 各メッセージのJSONのフィールド、プロトコルのバージョン番号 | 先頭にバージョン番号を入れる |
| TCPでのメッセージの区切り方 | 1つのTCP接続の中で、メッセージの境目をどう判断するか | 先頭にメッセージの長さを付ける（Network framework の独自フレーミング） |
| PINから共有キーを作る方法 | キーの導出方法（HKDFのパラメータなど） | ペアリングを作るときに決める |
| ペアリング解除の扱い | 片方で解除したとき、相手の端末にも伝えるか | 相手にも伝え、両方から削除する |
| ペアリングの組み合わせ | 端末がN台なら、組み合わせごとにペアリングが必要（Mac 2台とiPhone 1台で3回） | 仕様として受け入れる |
| メニューバーの画面構成 | メニューに何をどの順で並べるか、アイコン | MVPの画面を作るときに決める |
| iPhoneアプリの対応端末とアプリ名 | 今はiPhoneとiPad、アプリ名はBatonPhone | iPhoneのみ、アプリ名はBaton |
